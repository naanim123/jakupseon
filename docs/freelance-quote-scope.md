## 1. 결과물을 구체적인 단위로 적기

“상세 페이지 디자인”처럼 넓은 표현 대신 전달할 결과물을 나눠 씁니다.

- 상세 페이지 디자인 1종
- 최종 파일: 웹용 PNG 및 원본 편집 파일
- 기본 시안: 1안
- 납품 크기와 파일 형식: 사전 협의한 규격

범위가 아직 확정되지 않았다면 확정 전 가정이라고 표시하고, 변경 시 일정과 금액을 다시 협의한다고 적습니다.

## 2. 수정 범위와 피드백 기준 정하기

“수정 가능”만 적으면 오탈자 수정과 방향 전환을 구분하기 어렵습니다. 견적에는 수정 횟수와 1회 수정의 범위를 같이 적습니다.

예시:

> 시안 확정 후 세부 수정 2회가 포함됩니다. 새로운 방향의 시안 제작이나 합의한 범위를 벗어난 수정은 일정과 비용을 별도로 협의합니다.

수정 횟수의 계산 방식은 프로젝트에 맞게 조정하세요. 여러 피드백을 모아 한 번에 전달하는지, 요청을 받을 때마다 한 회로 보는지도 미리 합의하면 좋습니다.

## 3. 일정과 고객이 준비할 자료 정리하기

납기만 적으면 착수 조건이나 고객의 검토 시간이 빠질 수 있습니다. 아래 항목을 확인하세요.

- 착수 예정일과 최종 전달일
- 고객이 전달해야 하는 문구, 이미지, 참고 자료
- 고객 검토에 필요한 기간
- 고객 자료 전달이나 피드백 지연 시 일정 조정 방식

확정되지 않은 일정은 날짜를 단정하지 말고 “자료 전달 및 착수금 확인 후 영업일 기준 ○일”처럼 조건과 함께 적습니다.

## 4. 추가 요청을 처리하는 기준 쓰기

요청이 기본 범위에 포함되는지 불분명할 때는 바로 약속하기보다 변경 사항을 정리해 다시 확인합니다.

> 요청하신 추가 작업은 현재 합의한 범위에 포함되지 않아 별도 항목으로 정리했습니다. 추가 금액은 [금액], 일정은 [변경 일정]으로 예상합니다. 진행 여부를 확인해 주시면 반영하겠습니다.

금액이나 날짜는 실제 작업량을 확인한 뒤 채우세요. 도구가 계산한 값은 참고 초안이며, 최종 견적은 직접 검토해야 합니다.
